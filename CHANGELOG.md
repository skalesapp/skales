# **Changelog**

All notable changes to Skales will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## v12.9.65 - Close-Up

**This release brings scouts that keep working on their own, Flow that takes your files and zips, a lighter start, phone and computer in one conversation, errors that name their reason, attached files kept private, and Godot and whisper in one click.**

A scout now sets its own time to look again, keeps one thread per topic and can be allowed ahead what it may do without asking, and its approvals and pushes end when its run ends. Setup walks every step again with each one skippable, Settings open on the everyday rows and the chat list shows first what waits for you. A chat reaches the phone live and the phone shares it as this computer's own file. Errors from a provider say what the provider said, a self-signed certificate on your own endpoint can be trusted for that one address, and long chats and the app's first minutes get faster.

### Added
- **A self-signed certificate on your own endpoint can be trusted, for that one address.** When the connection map of a custom endpoint says this computer does not trust the server's certificate, a button under Server reads the certificate and shows its address and SHA-256 fingerprint. Only after you click Trust does Skales accept exactly that certificate for exactly that host and port, never for other addresses, never process-wide and never for a built-in provider, a Skales server or another fixed service such as Telegram, GitHub or a sign-in; a changed certificate is refused again. Your own speech server at the same address uses the trust too. Trusted certificates are listed in the endpoint's card and can be revoked there. A provider proxy keeps its own connection and does not use the trust.
- **Your own transcription server receives exactly the recorded audio.** Skales could send a short recording together with unrelated bytes from the same memory block, which a strict server refused or misheard; now only the recording itself goes out.
- **Godot 4 installs with one click.** Settings, System, Dependencies has a Godot 4 row that installs the official release for your computer into Skales' own folder, checked against the checksum file of the same release, on macOS, Windows and Linux. Whatever else was in that folder is kept beside it. The agent finds an engine there too, offers this install before it names any website, and asks every time before it installs.
- **whisper.cpp installs on a Mac without Homebrew.** Install builds it from the official source with Apple's Command Line Tools, every download checked against its checksum, and opens Apple's installer first when the tools are missing. Homebrew stays the fallback.
- **The phone shares a chat of this computer as this computer's own file.** PDF, web page and picture are made here with the same export Share writes, byte for byte, and the phone hands them to its share sheet; a file too large for the relay is named, never cut.
- **A new chat from a private chat on the phone stays private.** The branch lives only in memory here, never shows in History, and the phone opens it as its next private chat. A private chat answers only the phone it belongs to: an Incognito chat of this computer or another phone's private chat cannot be opened, shared, cut or branched from a phone, and a private chat's pictures come along into its branch.
- **A lesson an agent wrote twice reads once.** The memory file keeps what it has until the next lesson is added, nothing else is lost.
- **An automation can be renamed or deleted from the chat pane.** A More button in the pane head holds Rename and Delete, and the Flow window and the full view get Rename too; the same name shows everywhere.
- **Files you attached to a chat or sent from the phone no longer pile up.** They follow the working-folder days in Settings and go to the trash first, where they can be restored; nothing that any chat (even an old or archived one), a Flow project, a scout, an automation, a task or the memory still names is touched.
- **Your own token price for a custom endpoint's model.** Each custom endpoint card has two optional fields, input and output in USD per 1M tokens, for the model it uses. When the endpoint reports no cost itself, the cost display reads this price instead of showing nothing.
- **A crash screen leads straight to the bug report.** Report this crash opens the bug form with the crash already attached, so you only say what you were doing.
- **A fresh install opens Settings on Standard.** After setup Settings starts on Standard; Show everything, or answering that AI is familiar, starts it on Advanced, and a choice you made always stays. Existing installs keep what they have.
- **A fresh install starts with a calm composer, and nothing is gone.** The bar starts on the left with Mode and More beside it; More opens chat mode, agents, effort and access in the same row, and the bar stays open or closed as you left it. Whichever of them is switched on stays on the bar. Show everything on the last setup screen or in Settings brings them all back and stays. An install from before this update keeps its bar as it is, and an experienced level always shows everything.
- **An approval card leads with one sentence in normal words.** It says what the call does and what happens next, the same sentence in the chat, in Code, in a scout's thread and on the phone, made by rules and not by a model. A command or tool it cannot read fully gets a neutral sentence, and the real command stays on the card. Only a call that just reads or searches inside the project, and touches no secret file such as .env, a key, .ssh or .git, folds its real command behind the sentence on the calm card; a write, a delete, a copy, the network, a schedule, a send or any unknown tool keeps it open on every card. A link is named by the host it really goes to, and only a web link has one, a path by its place in the project or its full folder outside it, a long name is shortened in the middle so its end stays, two calls that share an id get the neutral sentence, and characters you cannot see never reach the sentence.
- **Setup walks every step on a first run again, and almost every step can be passed without an answer.** After the language, the licence 1.3 and the notice it asks how much AI you have met, your name and job, interests, how you will use Skales and which add-ons come along, the look, your provider, place and weather, notifications, voice, safety, whether Skales may work in the background, whether usage data may be sent (off until you say yes), the features with your buddy and pairing your phone. The step counter counts each screen once and starts at 1, and the closing screen says Skales remembers your answers only when you gave some. Installed copies see no change and keep every setting.
- **The chat list shows first what waits for you and what is running.** Waiting for you and Running stand on top only while they hold a chat, with one line saying what it does right now; a finished chat falls back to its own place, its pin, group and order unchanged, and a run that died stands in neither.
- **The chat list filters by Running/waiting and Unread, and several chats can be selected at once.** Move, archive or delete a selection in the sidebar and in History, and a search hit in History names its group or project.
- **A shared visual in Discover stands as a card and runs only once it is opened.** The feed shows its picture or a calm tile and costs no CPU; Open fullscreen runs the page in one frame with Save as image, and closing ends it, so it starts over the next time.
- **Pages in a chat stand as a light card and open in the side panel.** A web page, a Skales Visual and a diagram show a title, a type, a picture of the result or a calm tile, and an Open button. The page runs only in the panel's new Preview view, one at a time, so a long chat stays light. An older page keeps a calm tile; a diagram always gets its picture. That picture is drawn with no network and no reach into your files, and a page that never finishes is ended after 20 seconds. A visual in Discover draws only while it is on screen.
- **A scout can have several threads, one per topic.** Each has its own conversation, turn, tasks, follow-up, cost and cards; memory and files stay shared, and a scout with one thread looks as before. Two threads work at the same time in one computer, each in its own folder, and a step that needs the machine or the browser another thread is using waits and says for whom. Open one from the scout's menu; the scout can open them too, read across, hand a message over, and turn a thread into a routine or a trigger. Threads that wake each other stop after three turns without you, with one line in the thread, until you write. Every result file reaches you once, in the thread that made it. Deleting a thread clears its times and cards and nothing else, and hands out what it still held in the first thread. On the phone too.
- **A scout can be allowed ahead what it does without asking.** In its settings: writing files in its own folder, single ordinary commands, web actions and forms, and any connected app set to "Act without asking", which runs steps that read or make a small edit. Sending, deleting, paying, scripts and package commands such as npm run always ask, also at night, except a script inside a scout's own closed-off computer, and so does whatever the check cannot read, such as Enter in a form it cannot see or an unknown app verb. Its thread shows one line for every step that ran on such a right.
- **The first run asks whether Skales may keep working in the background.** Yes turns Autopilot and Friend Mode on, no leaves them off; the screen names the cost, the safety mode and how to stop it. Existing installs are not touched.
- **A scout sets its own time to look again.** After every conversation one follow-up stands in the thread, with its reason, without any setting. If you write first it is dropped and what the scout meant carries into your conversation. A scout can also repeat a time as its own routine. Times stay inside budget and quiet hours, never start a second run beside an open approval, and share one run with a round in the same hour. You delete them on the Scout page or on the phone; out of budget or without a provider, a due time stops and says so. **This runs on your own key after the update, without a new setting:** each look is a run on your key like any other run, so it costs like one, booked on the scout's budget. The first time a scout does it, one line in the thread says so, what it costs and how to stop it: delete a single time, or pause or delete the scout. A time is at least 15 minutes away, and two repeating times that would run as good as double are not stacked.
- **A scout also wakes in a window and after long silence.** A round waits for a quiet moment while you are in the conversation, and a scout with nothing planned looks around after a day of silence, then less often as long as nobody answers.
- **A routine that brings nothing pauses itself.** A week of nothing new or of reports nobody answered pauses it, one line in the thread says so, and a card starts it again with one Yes. Without an answer it stays in the Schedules list as paused, where one tap starts it.
- **A scout set up in the evening gets that day's summary too,** instead of its first one a day later.
- **A quiet run names what it checked.** Its line in the activity and under the thread says what it looked at and that nothing new came, and wakes nobody.
- **A normal chat reaches the phone live.** Its words go out as they are written, on the wire a scout's run uses, whether the message came from the phone or was typed here. Older phones are not touched, the browser extension gets its progress as before, and a private chat stays on this machine unless the phone sent it. Only the phone with that chat open gets the words, and a private chat's words never leave this computer.
- **A phone can read every file a scout made.** The computer lists all of a scout's result files with size and the task each came from through a call of its own, so the scout's pane stays small and an older phone keeps working.
- **A scout's run reaches the phone live.** Its words, steps and working state go out on the wire a chat turn uses, Stop on the phone ends the run that thread stands for while a scheduled or group run beside it keeps working, and a closing thread row tells an open phone to read again. A scout's approval also carries its look, so its banner shows its own fish.
- **Outlook with Exchange on-premises is described, and the pane says why Graph is missing.** The Office guide and the extensions page have a section on versions (Exchange 2016 and 2019), installation by the administrator and the role My Custom Apps; on an on-premises mailbox the Outlook pane shows the reason in your language instead of a Connect Microsoft 365 button that cannot work.

### Fixed
- **The buttons at the top of the Code page answer every click in the desktop app.** The window's drag strip lay over the Code title bar and took the clicks on the upper part of Terminal, Settings and the preview button; the Code page now starts below the strip, as the sidebar does.
- **Fetching the model list of your own endpoint names a certificate this computer does not trust.** Both Fetch buttons on the card said nothing was listening at the address; they now give the certificate as the reason and offer the same trust card as the connection check, and a list refused over it is fetched again once you trust it.
- **The model list in setup and the LibreOffice row in Settings speak your language.** Fetching models for your own endpoint during setup now names an untrusted certificate and why, instead of "fetch failed", and the LibreOffice line under Dependencies is translated in all twelve languages like the whisper and Godot rows.
- **The Code and Flow preview loads in the desktop app.** A preview page could stay blank with too many redirects, because the signed pass for its files was lost on the way to the page and the page was sent to fetch a new one again and again; the pass now arrives with the page, still for that one project and only until it expires.
- **Times of day show in the app language, never with AM/PM in a German app.** The planner, its settings, automations, routine templates and the Autopilot time window pick times from the same list as the scout settings, labelled in the clock of the interface language instead of the operating system, and a stored time between the steps is kept.
- **An automation that fires on several events keeps each of them.** A short event, such as a file whose name is part of a longer one that landed before, is no longer taken for that one and dropped, and the task that carries several events names all of them in its title.
- **The line about left-out tool results comes once, not every turn.** On a small model window the conversation says which older results were left out when that first happens and again only when the window or the reason behind it changes.
- **The planner settings refuse a day that ends before it starts.** Picking an end time at or before the start keeps the old time and says why, in place of saving hours the planner would later reject; an old stored time such as 9:00 reads as 09:00 and an empty one shows --:--.
- **An approval card that changed while you answered it is replaced by the new one at once.** When a run already asks a newer question than the card you answered, the open chat keeps following the run and shows the new card, instead of dropping it until you reload the chat.
- **A waiting approval stays on screen when its stored question cannot be read for a moment.** The sidebar, the phone and the coding sessions keep showing such a run as waiting instead of hiding a card you can still answer.
- **A private chat sends an email or makes any other change only once per step, like every other chat.** A step a private run repeats, also in work it hands on to run later, returns the first result instead of acting twice. The note of what was done stays in memory only and ends with the private chat, so nothing of it reaches the disk.
- **A scout's run reaches the phone right after this computer starts again, and keeps reaching it during a chat.** This computer keeps what your phone said it can read with the pairing, so after a restart a scout at work shows on the phone at once instead of only after the phone reconnects, and the short greeting a phone sends with every chat message no longer switches the scout's run off on the phone.
- **Only the phone a private chat belongs to can end it.** When another phone sends the end of a private chat that is not its own, or of an Incognito chat on this computer, it is told that chat is not open on it, instead of being told the chat is idle. Nothing of the other chat ends, as before.
- **A page preview that stays in view gets its picture.** When many previews ask for their picture at once, one that had to give way asks again as soon as there is room, instead of keeping the plain tile until you scroll it out of view and back.
- **An answered approval stays answered, and the next one waits at once.** After you answer an approval in the open chat, Waiting goes for exactly that card: a second question of the same run shows as waiting right away instead of after a few seconds, and the card you answered never comes back as waiting later. When your answer could not be sent at all, the card is back on screen at once.
- **A question nobody can answer any more no longer reads as waiting.** The phone's chat list, a chat the phone opens, the coding sessions and History's Running now ask the same question the sidebar asks before they show a run as waiting or running: whether a run on this computer still holds it or its question is still open. A run left behind by a restart or whose question lapsed is no longer listed there.
- **A scout question the phone holds clears even when a stored question file is broken.** A question file that holds no readable question counts as read without a card instead of keeping the phone's list incomplete for good, so a card that was answered or dropped leaves the phone. The file stays where it is, and once it is written anew it is read again; a file the system only refuses for a moment still keeps the list open.
- **An opened list of memory sources under an answer stays open.** Scrolling far away from it and back no longer folds it shut.
- **A jump to an older message stays on it while the chat around it fills in.** Opening a message that first had to be loaded no longer drops the view half a screen away a moment later; any scroll of yours takes the view back at once.
- **An open preview pane shows the new answer when you regenerate or switch versions.** The pane used to close; it now shows the page at the same place in the new answer, and closes only when that answer has none.
- **Settings opens without waiting on slower work of the window.** A direct open or a quick reload of Settings could sit on the spinner for a long time while other requests of the page were answered first; it now reads its settings on its own request and opens as soon as they are there.
- **Save as image never reaches this computer through a public name.** A page whose web address resolves to this computer or its local network, is refused that request when it is drawn into a picture, as an address written as a local one already was. Without a proxy a name that does not resolve is refused as well, and the picture connects only to the address that was checked; behind a system proxy the picture goes out through that proxy as before.
- **Save as image in a browser says what it saved.** Outside the desktop app the button saves the page as an HTML file, and now says so next to it, with a note that a picture is made in the desktop app.
- **A reply that explains itself and then hands over an HTML page shows both.** The words written before the page now stand above its preview card, and anything written after it below, instead of the card alone.
- **Link cards under a reply with an HTML page come from its words.** The links written around the page get their cards, and the page's own image and style addresses never do; a code block written before the page stays a code block above it.
- **LibreOffice and the Godot export templates install once at a time.** A second start while one Skales is already installing them, from another window or a second Skales, now says in your language that another install is running instead of downloading into the same folder.
- **A Word file with a pictures folder entry opens again.** Reading a .docx whose archive lists its media folder as its own entry stopped with an error; it now reads the text and names the pictures.
- **A Word file's empty notes no longer show up as headings.** Reading a document no longer lists an empty Footnotes, Comments, Headers or Footers section; a part with text keeps its heading.
- **Flow calls an attached archive by its folder name.** An archive attached to a Flow project unpacks into its own folder under assets/, and the agent is now told each folder name word for word, so it talks about the material by the name you see in the project instead of a generic "pack".
- **An IBAN in an attached file is hidden whole, as an IBAN.** An IBAN written in groups is never half shown with the rest hidden as a phone number, the example IBANs from the textbooks included, and an IBAN followed right away by its BIC or a word in capitals is still recognised.
- **The Safety mode notes name installing Godot.** Settings lists installing Godot from the agent among what asks in every mode, because it always asks first, in all 12 languages.
- **A file attached in a chat reaches the model with its contact details, keys and payment data hidden.** E-mail addresses, phone numbers, keys and card or bank numbers in a file you attach (the paperclip, an @-mention, a file sent from the phone) are masked before the model reads it, on every surface. What you type yourself stays as you wrote it. If the check cannot run, the file is not sent and the answer says so. Code keeps asking before it sends a file that holds secrets. A copy the model reads later with read_file or read_document is masked the same way, a file name with a bracket in it is found, and words you type after a file are never part of it. Phone numbers are found in the shapes people write them (with a plus or 00, a national number with an area code, after "Tel", full-width digits), while an order number, a timestamp or a hash is left alone, and a very large file is checked as fast as a small one.
- **An attached file restored from the trash stays hidden from the model the same way.** Contact details in a file the clean-up moved to the trash and you brought back are still hidden when the model reads it, also after a long time with many attachments.
- **A private chat you leave on the phone ends on the computer too.** Closing it, starting a new chat or leaving it ends the conversation the computer held for it, together with the masks and files painted or sent in it; a phone that starts again ends all of them. A private branch ends the same way. Normal chats keep their masks as before. A phone that has sent nothing for 30 minutes (it crashed or lost the network) ends its private chats here as well.
- **A local model that keeps repeating itself is stopped, with the reason.** When a model on your computer or network writes the same text over and over, in its answer or in a think block it writes inline, the answer is stopped where the loop began and says why, instead of running until the budget is gone. Cloud models, long tables, generated pages with long runs of spacing, a quoted document or a repetition you asked for are left alone. The code builder uses the same check for local models.
- **Obsidian finds what the model searches for.** A vault search now matches notes that hold every word of the query in any order, not only the exact phrase. A pasted vault path works with quotes, `~`, `file://` or the `.obsidian` folder of a vault (a `.obsidian` folder with no vault around it, such as one in your home folder, is named as Obsidian's settings folder instead of connecting the folder above), and a folder the system refuses to read says so in Settings and to the model instead of looking like an empty vault.
- **A dropped connection is named.** When a provider such as DeepSeek closes the stream mid-answer, the chat says the connection was interrupted instead of "an error Skales does not recognise", and a proxy page where an answer was expected points at the base URL.
- **Crash reports say what to fix.** With anonymous usage statistics on, a crash now also sends the error's type, the React error number and which part of the screen failed, all from fixed lists, never the message. The phone sends the same fields.
- **Buttons and forms in generated apps work in the preview.** A form's Add button and alert or confirm dialogs now work inside the sandboxed preview; the page still cannot navigate away or reach the network.
- **A `.md` file opens in place.** Markdown files served to the app window show as text instead of downloading.
- **MiniMax-01 is recognised as seeing images.** A picture you attach goes to it directly, and Settings shows it as a model that can see.
- **The Tasks page no longer breaks when it finishes loading.** Two layout settings were read after the loading screen, which React rejects once the list has loaded; they are now read first.
- **Tool downloads get through a GitHub outage.** When GitHub's release host answers with a server error, whisper.cpp, Godot and its export templates come through GitHub's API instead, checked against the same checksum. Downloads follow redirects only to the hosts they come from.
- **Repair no longer reports mermaid as missing.** Folders in the server packages that hold only a file read by path are checked for that file, not as packages.
- **A Scout sheet action this computer does not know is refused with its reason.** A phone that says it reads the refusal gets it; an older phone keeps the reading it always got.
- **Every request from a phone that names a private chat is checked against that phone first.** A phone reaches only its own private chat, by its id or this computer's; anything else, a Stop included, is refused with its reason instead of answered as idle.
- **A private chat on the phone after this computer restarted says so.** The next private message is answered with "The computer was restarted, so this private chat has ended there" instead of quietly starting an empty chat.
- **The phone learns the relay's file limit from this computer.** The hello answer names the largest file one relay message carries.
- **Flow takes attachments of any size at the start.** A zip or picture over about 700 KB is streamed into the project instead of breaking the start with a server error, and a file that cannot be attached is named with its reason while nothing is started and no empty project is left behind.
- **Files added during a Flow session, and picture swaps in the inspector, go the same way as the start.** A large zip lands as one folder in the project's assets and is named to the agent on the next turn.
- **Large logos, fonts, brand assets, PDFs, plugin packages and long scout voice messages arrive whole.** Each of them is streamed first when it is too large to send directly, instead of failing with a server error.
- **Large Excel and Word files and large private attachments in chat arrive whole.** They are streamed first like a large PDF, instead of failing with a server error.
- **A zip attached to Flow stays inside its own folder.** An archive with a name made only of dots, or one that unpacks into far more than it weighs, can no longer write over the project or fill the disk, and a second archive of the same name unpacks beside the first instead of into it.
- **A Flow start in progress survives a second window and a reload.** A duplicated tab or a window opened from it no longer removes the project the first window is still starting, and a project with a run, a queued order or a finished attachment is kept.
- **Uploads clean up after themselves.** A file streamed without a size is held to the room on the disk, half-finished uploads left by a closed app are cleared when the project opens again, and files waiting for an action use a random name only the sending window knows.
- **A private PDF or Office file without readable text is kept.** A large one is held privately before its waiting copy is removed, so it attaches with a note instead of disappearing, and a waiting copy no longer stays on disk when the conversation moves on.
- **Uploads running side by side share the disk.** Two large files arriving at once can no longer both count on the same free space, a file sent without a size stops at 200 MB, and half-finished uploads in the Workspace and transcription folders are cleared at start.
- **A Flow start in a background window is kept on reload.** Another window removes a start only once it is two minutes old and its window still does not answer.
- **A template's brief that waits behind a running turn still shows as its card.** Sent while a turn works, from the computer or the phone, the brief waits in the queue and appears as the same card as when it goes out at once, also after a restart.
- **What's new lines its cards up.** The pictures of a row are the same height and every title starts on one line, however long the text under it runs.
- **The run's activity line shows your agent's emoji.** While a reply works, the line that says what it is doing now wears the emoji of the active agent instead of the Skales mascot picture, like on the phone.
- **Settings search finds a row by its printed name, and Show everything.** Typing a row's name as printed, punctuation included, now lands on it.
- **Waiting for you ends at once when you allow an action.** The sidebar zone no longer lingers for a couple of seconds after the card is gone.
- **A half-typed first message stays in the new chat.** Opening an existing chat from a link no longer pours it into that chat's composer.
- **Waiting for you counts the same everywhere and ends the moment you answer.** The folded sidebar button, the Waiting block and the phone use one rule for what waits, and an open chat leaves Waiting as soon as you answer its card instead of at the next refresh. Your phone hears about an approval even when no run stands behind it.
- **The Show everything switch in Settings tells the truth.** An install with an experienced level and without the mark now sees the switch on, as the app behaves.
- **Pictures of pages in the chat are no longer pushed out by the feed.** When many cards ask at once, the ones from the feed give way first and ask again when they come into view.
- **A folded sidebar is only the round button.** The grey bar around it is gone in every theme and the page shows through, and a dot on the button tells you when a scout, the cockpit or a notification is waiting.
- **Sending in a long chat keeps you at the end.** When the older messages came back as the turn started, the view could drop far up and stay there for the whole turn, and the answer ended out of sight.
- **A page in a chat gets its picture on the card now.** The check for incognito ran where it could only fail, so no picture was ever kept; a message that ended also lost track of the pictures it still owed. Off the record nothing is drawn or kept, as promised.
- **A scout stays held while its question about a run's cap stands.** It used to go on with the next tick and announce a new month in its thread; now it waits for your answer, and a no leaves the capped run where it stopped while the scout's other work goes on.
- **The word stop in a scout's thread also deletes the times the scout set itself there,** follow-up included. Routines you set and rounds stay, the long silence counts anew, and the next conversation sets a follow-up again.
- **A yes or a no on a scout's card counts only in the thread it was asked in.** The same step in another thread gets its own card and takes nothing from the first.
- **Stop also closes the cards a scout's finished turn left open,** so a late answer starts nothing, and ending a scout also clears its own times, so nothing of them fires when it comes back.
- **A scout's pane shows its newest finished tasks and files after more than 40 runs,** not the oldest ones, and a phone is never sent a path on your computer.
- **A phone tells you why a scout on your own computer has no picture.** The computer now marks such a scout in its Live frame, so the phone shows the same sentence as the Live card instead of asking you to set up a workspace.
- **A scout answers in the language you write in, not the app's.** A wake-up without a new message goes on in the language of your last message in its thread, and the line after a restart names the scout instead of the app.
- **A scout that works on your own computer says so on its Live card.** It has no picture of its own and nothing to take over, so the card names that instead of offering to set up a workspace.
- **The morning round and evening summary times of a scout follow the interface language clock.** No more "09:00 AM" in a German app.
- **A phone can let go of a question from a scout you deleted.** The computer answers for a scout that is gone with an empty, complete list. A scout whose file cannot be read is not called gone.
- **A scout's question pushed to a closed phone carries the words its fish is drawn from,** and gives them up first when the sealed preview would not fit.
- **An incognito chat now gets its first answer instead of the run ending before the first request.** The run read a saved tool journal that an incognito chat deliberately does not have; it now treats that as empty and writes nothing to disk.
- **A scout that finished stops asking.** When a run ends, its open network questions close on every surface, its browser tabs close, a tab that would not close is tried again, and its computer reaches nothing until the next task, so a video left playing can no longer raise an approval for work that is long over.
- **Stopping or deleting a scout takes its questions with it.** Ending a scout closes all its open approvals on the computer and the phone, including what was still waiting to be sent. A scout that no longer exists never sends a push.
- **One push per approval, plus one reminder.** A network card that gains another name or more bytes is redrawn without calling the phone again, and the push names the scout that asks. A declined upload stays declined for the task instead of asking again on every retry.
- **A scheduled job no longer stacks up.** A job that fires while its task is still open joins that task, whether the clock, Run now, a playbook or an event fired it, so a computer that slept for three days wakes up to one run. ## v12.9.60 - Scout 🐡

**A release about a helper that keeps working while you do something else: Skales Scout, a lasting agent that lives on your computer with its own thread, memory and rhythm, can get a small computer of its own, and checks in with you on the computer and on your phone.**

A scout has a name, a role and a personality, lives in one thread for months without losing track, and remembers what it learned. It can get its own small virtual computer on a Mac, on Windows and on Linux that reaches the internet but never your home network; you watch it work live, take it over, and its results come back to you as files you can open. Without being asked it keeps a day: rounds, a standup and an evening summary, goals over several days split into parts, and suggestions you answer with Go or Wait. A lead scout shares work with its sub-scouts and short-lived helpers, each scout can have its own model and a daily budget with the cost of every run in view, and a fallback model is never used in silence. Approvals say how far your yes reaches, sites, purchases and a mailbox of its own are allowed per scout, and sign-ins stored once in Skales Vault are handed out entry by entry.

Your phone runs alongside: the same Scout page, questions, approvals, settings and sub-scouts, with a scout that can live on the phone alone when there is no computer. Around Scout, automations can be built on a canvas or by saying so and started by a webhook, a file, a calendar event or another run, and a chat switched to the Automation mode builds one beside the conversation, on the same canvas Flow opens; slides, a document or a note sit beside the chat and change exactly where you comment; every message takes reactions; chats sort into groups and projects; and Skales runs natively on Windows on Arm.

- **A scout's approval now says how far your yes reaches.** When a scout wants to send, post, pay or delete something outside its computer, its card shows who gets what and lets you allow it once, for this session, for this task, until a time you pick, or always; every wider yes covers exactly one recipient and one kind of action and shows up in the scout's pane with when it was last used and a Revoke button. - **Several scouts can share one group thread with you and hand work out among themselves.** You pick the scouts, give the group a name and write in it like in any thread: name one with @ and exactly that one answers, ask everyone and each adds only what is new, otherwise the group's lead answers or passes your question to the scout whose job fits. Scouts talk to each other at most three rounds per topic before the question comes to you, and a split they propose only counts once you confirm it. The group shows who is working right now and what it cost in total. Each scout keeps its own thread and memory, and /groupchat stays as it is.
- **A lead scout now shares work with its sub-scouts and short-lived helpers.** It hands a sub-scout a task in that sub-scout's own computer and gets back what was done, the result, what is still open and what it cost; a helper runs a short errand inside the scout's computer and can never send anything, write memory, add tasks or pass work on. There is nothing to click yet; the Scout page comes next.
- **A scout now remembers, has a personality and keeps a daily rhythm.** Each scout keeps its own memory, apart from yours: working notes it writes freely, and a small core plus what it knows about you, which change only after you confirm them, can be undone line by line and never take in what a web page or a mail told it. At night it condenses older notes into a searchable archive inside its budget. You pick its personality, which sets the tone and never the care, and every scout lives in exactly one thread named after it. It brings a morning standup (done, running, needs you, skipped with the reason, cost) that you can answer with yes, no, go or wait, looks around for news on its standing orders one to twelve times a day, keeps its own versioned skills that run only in its own computer, and stops with a short reason when it notices it is going in circles.
- **A scout lives in one thread for months without losing track.** Each scout has exactly one conversation, listed once under its name. What it owes you is kept as tasks outside the conversation and read fresh before every answer, so two similar jobs never blur into one and a promise from weeks ago is still there. Longer work runs on its own and reports back into the thread. When the thread grows long, older parts are condensed after everything worth keeping was saved; a quiet line marks the spot and the full text stays searchable. Messages you send while it works reach it at the next step, a plain "stop" ends what runs, it does not repeat news you already have or topics you turned down, and a reaction on a message tells it how it did.
- **A scout's own computer arrives as one signed download.** The scout workspace is a small Linux system built on Debian with Chromium, Python, Node and git, about 0.5 GB to download and about 1.7 GB on disk, shared by every scout on the machine. Before the download Skales tells you how big it is and whether it fits, with the real numbers; the download shows its progress, can be cancelled and continues where it stopped, even after a restart; a damaged file is fetched again; and the image is checked against its signature before every start, so a changed file never runs. When a newer workspace arrives, new scouts use it while existing ones keep theirs until you reset them, and a workspace nobody uses any more is removed so the space is really free. The open-source parts of the workspace and their complete source code are linked from the Scout page and the third-party notices.
- **On a Mac, each scout now gets its own computer: a small virtual machine that only it works in.** It starts in a few seconds when the scout needs it, can be paused and stopped any time, and stops when Skales quits, also when Skales is closed by force; after a restart it reads as stopped instead of guessing. The machine has no network card, no shared folder, clipboard, USB or sound, and its own disk layer over the shared workspace, so deleting it gives the space back. It runs on Intel Macs from macOS 12 and on Apple silicon, through a small signed helper that alone holds the permission to run virtual machines. If a Mac cannot run one, for example because Skales itself runs in a virtual machine, or memory or disk are short, the Scout setup says exactly that, with the numbers and what to do. A freshly downloaded workspace also starts right away instead of checking its whole disk a second time.
- **On Windows and Linux, each scout gets its own computer too.** Windows runs it with QEMU on the Windows Hypervisor Platform, Linux with Cloud Hypervisor on KVM, both as the logged-in user and both shipped with Skales, so there is nothing extra to install. If Windows has the Hypervisor Platform switched off, the Scout setup explains why it is needed, switches it on after Windows asks for an administrator's confirmation, offers the restart now or later and carries on where it stopped once Windows is back. Programs that may not run alongside it (older VirtualBox or VMware, some Android emulators) are named first. When a computer cannot run a scout at all, it says exactly why and what helps: virtualization switched off in the BIOS/UEFI, a Linux user who needs the kvm group (with the command to copy), a login that started before that, or Skales itself running inside a virtual machine without nested virtualization.
- **A scout now really works inside its own computer, and its results come back to you as files you can open.** Commands, scripts, file edits and searches of a scout run in a locked-down space inside its computer, one folder per task, without network or access data, so a scout never touches the files on your machine. What a task leaves for you is copied out as a file card in the scout's thread: plain files only, up to 100 MB each and 500 MB per task, never with run permissions. Links, device files and odd names are refused one by one, each with its reason, and a file only goes into a scout's computer when you give it. Its skills run there as well, and Skales keeps track of how much memory and disk the computer uses and whether one more scout would still fit.
- **A scout's computer reaches the internet, but never your home network.** It has no network card of its own; every connection goes through Skales on your computer, which looks up the address itself and refuses your router, NAS, printers, your computer's own services, Tailscale and cloud metadata addresses, however the address is written. Every connection is listed per scout with time, destination, size and the reason when it was refused, and a scout can be limited to a list of domains.
- **You can watch a scout's computer live and take it over.** In a scout's thread the side panel shows its screen as it is right now, marked beta. When the scout needs you, for a login or a captcha, it asks: click Take over, use keyboard and mouse in the picture, and Give back when you are done. While you have it the scout waits, and afterwards it looks at the page again before it goes on; what you type is never stored. When there is no picture, the panel says why instead of showing a black square. The scout browses with the same browser tools as your chats, but in the browser of its own computer, so your own browser and a chat's live view never see its pages.
- **A scout's computer can run for weeks without clogging yours.** Before each task it takes a snapshot of the scout's computer, keeps the newest five and says which older ones went; a task that went wrong can be rolled back from the side panel. "Reset workspace" gives the scout a fresh computer while its thread, memory and files stay, and "End scout" stops everything, keeps the thread and can delete the computer, naming the space that came back. After a quarter of an hour without a task the computer rests, hands its memory back and wakes for the next task; after your computer sleeps it carries on and folds what it missed into one run instead of catching up hour by hour. The side panel shows memory, disk and CPU against their limits, your computer's free room and what one more scout would need, each saying when it runs short. New in Settings > Desktop app: Home server starts Skales at login without a window and keeps the computer awake, so the scouts keep working in the background while this window and your phone look in.
- **Triggers: a webhook, a file in a folder, a calendar event or another run can start a job or wake a scout.** On the Schedule page a new job can now be fired by a webhook with its own address and secret (reachable from the internet through the Skales relay only if you switch it on), by a calendar event a set number of minutes before it starts, or by a scout run that finished or failed, an approval you granted or a budget share that was crossed. Any trigger, including clock, folder and mailbox, can wake a scout instead of running a job. Every event fires once, a reminder or file missed while Skales was closed is caught up once when it opens, follow-ups stop after three in a row, and a trigger aimed at a scout whose budget is spent waits and says so. A scout's side panel and the agent editor list what wakes them, with pause in place, and you can set it all up from the chat too.
- **A scout works with your connected apps.** Every app connected in Connect apps (built-in connections, API connectors and MCP servers) now reaches a scout with the same tools the chat uses, at the level you set for it: off hides the app, read only keeps the reading steps, drafts adds drafts, and every step that changes something waits on the scout's approval card. A sub-scout never goes further than its lead; moving money, payments and your own mail never reach a scout this way.
- **Scouts, Buddy, the Organization and Studio Flow show results as cards.** A list of places, recipes or products a scout or Buddy hands over shows as the chat's card row under the answer, files made along the way show as the chat's file cards, a comment sent from the document panel into a scout's thread keeps its card, and each agent's answer in an Organization run carries its own files and cards.
- **Give a scout its own server.** In Settings, Servers, a profile (FTP, FTPS or SFTP, with a password or a key) can now be assigned to a scout. That scout reaches its own servers with the stored login and no other profile: not yours and not another scout's. Changes on a server still wait on the scout's approval card. Deleting a scout gives its servers back to you.
- **Mail with TLS off no longer logs in in clear.** A mail account or a scout's mailbox set up without TLS now upgrades with STARTTLS whenever the server offers it, for reading as it already did for sending, so the password never goes over the wire unencrypted.
- **Mail and file servers must show a valid certificate.** Mail accounts (yours and a scout's mailbox) and FTPS profiles now check the server's certificate, and a self-signed or invalid one is refused with its reason. For a server you run yourself, switch on "Allow self-signed certificate" in that account or profile. SFTP profiles keep the host key seen first and refuse a changed one; the same switch takes on the new key after a reinstall. Accounts and FTP profiles you already had keep working: the switch is on for them.
